# Kth Smallest Element in a BST

## Intuition

### In-Order Traversal Property

An **In-Order Traversal** (Left Subtree $\rightarrow$ Node $\rightarrow$ Right Subtree) on a Binary Search Tree (BST) visits nodes in strictly ascending order.

By running an in-order traversal, the values are naturally flattened into a sorted list:


$$\text{Sorted List} = [\text{1st smallest}, \text{2nd smallest}, \dots, k\text{-th smallest}, \dots]$$

### Optimization: Early Stopping

Your code works by traversing the entire BST and storing all $N$ values in an `ArrayList`, then returning the value at index `k - 1`.

While correct, collecting every node takes $O(N)$ extra space and time. We can optimize this by maintaining a running counter of visited nodes during the traversal. The moment our counter reaches $k$, we record that value and immediately terminate the traversal early, taking only $O(H + k)$ time and $O(H)$ space.

---

## Step-by-Step Guide

1. Define a global counter variable `count = 0` and a result holder `res = -1`.
2. Start an **In-Order Depth-First Search (DFS)** starting at the `root`.
3. **Base Case Check:** If `node == null`, return.
4. **Left Branch:** Recursively visit `node.left` to process all strictly smaller values first.
5. **Process Current Node:**
* Increment `count` by 1.
* If `count == k`, we have found the $k$-th smallest element! Save `res = node.val` and stop further recursive processing.


6. **Right Branch:** If `count < k`, recursively visit `node.right`.
7. Return `res` once the traversal completes or stops early.

---

## Complexity Analysis

* **Time Complexity:** $O(H + k)$
* Where $H$ is the height of the tree. We traverse down to the leftmost node in $O(H)$ steps and then visit exactly $k$ nodes in sorted order before stopping early. In the worst-case scenario where $k = N$, this takes $O(N)$ time.
* *(Note: Your provided full-traversal approach takes $O(N)$ time regardless of $k$).*


* **Space Complexity:** $O(H)$
* The auxiliary space is determined by the depth of the call stack generated by recursion, where $H$ is the height of the tree.
* **Balanced Tree:** $H = O(\log N)$ space.
* **Skewed Tree (Worst-Case):** $H = O(N)$ space.
* *(Note: Your provided approach uses $O(N)$ space to store the list of all nodes).*
