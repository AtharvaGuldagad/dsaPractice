# Balanced Binary Tree

## Intuition

### The Height-Balanced Condition

A binary tree is height-balanced if, for **every single node** in the tree, the height difference between its left and right subtrees is at most 1, and both its left and right subtrees are also height-balanced.

### Bottom-Up Post-Order DFS

A naive approach calculates the height of the left and right subtrees for every node independently. However, that leads to an $O(N^2)$ time complexity because heights are repeatedly re-calculated for lower nodes.

By using a bottom-up Depth-First Search (DFS) post-order traversal, we evaluate the bottom-most leaves first and return two pieces of information up to the parent node:

1. **Is the subtree balanced?** (Represented as `1` for true, `0` for false).
2. **What is the height of the subtree?**

This allows each node to immediately check if its subtrees are balanced and calculate its own height in $O(1)$ time by taking $1 + \max(\text{left height}, \text{right height})$. If a subtree anywhere down the line is ever unbalanced, that status propagates all the way back up to the root, avoiding any redundant height checks.

---

## Step-by-Step Guide

1. Start a recursive DFS traversal at the root of the tree.
2. **Base Case:** If you land on a blank spot (`null`), return a result pair: `[1, 0]` (meaning it is balanced, and its height is 0).
3. Recursively call your helper function on the **left child** to retrieve its balance status and height.
4. Recursively call your helper function on the **right child** to retrieve its balance status and height.
5. Evaluate the current node's balance status:
* Is the left subtree balanced? (`left[0] == 1`)
* Is the right subtree balanced? (`right[0] == 1`)
* Is the height difference between left and right subtrees at most 1? (`|left[1] - right[1]| <= 1`)
* If **all three** conditions are met, mark the current node as balanced (`1`); otherwise, mark it as unbalanced (`0`).


6. Calculate the current node's height: $1 + \max(\text{left height}, \text{right height})$.
7. Return the new pair `[balance status, height]` back up to the parent caller.
8. Once the recursion unwinds back to the root node, check its balance flag. If it is `1`, return `true`; otherwise, return `false`.

---

## Complexity Analysis

* **Time Complexity:** $O(N)$
* We visit every node in the binary tree exactly once using post-order DFS. At each node, computing the height and balance condition takes $O(1)$ constant-time operations. Thus, the execution time scales strictly linearly with the number of nodes $N$.


* **Space Complexity:** $O(H)$
* The auxiliary space is determined by the maximum depth of the call stack generated by recursion, where $H$ is the height of the tree.
* In the worst-case scenario (a completely skewed tree like a linked list), $H = N$, giving $O(N)$ space complexity.
* In the best-case scenario (a completely balanced binary tree), $H = \log N$, giving $O(\log N)$ space complexity.
